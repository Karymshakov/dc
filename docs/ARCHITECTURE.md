# Архитектура работы над ТЗ 7

Документ описывает две вещи: устройство кода и устройство процесса,
которым этот код доводится до сдачи.

## Часть 1. Код

### Принцип

Одно правило спеки — одно место в коде. Если правило нельзя показать пальцем
в одной функции, оно будет нарушено при первой же правке.

```
main.py                     единственная точка входа, без зависимостей
└── src/rsrp_coverage/
    ├── config.py           ВСЕ числа спеки. Единственный файл, где они есть
    ├── geo.py              гаверсинус + локальная равнопромежуточная сетка
    ├── cleaning.py         шесть правил отбраковки + дедупликация
    ├── grid.py             агрегация в клетки, медианы, цвета, худшие
    ├── siting.py           допустимость площадок, покрытие, выбор пары
    ├── mapping.py          HTML-карта на Leaflet
    ├── pipeline.py         сборка: соединяет шаги, больше ничего не решает
    └── cli.py              аргументы, вывод, самопроверка
```

### Решения, которые выглядят странно и почему они такие

| Решение | Почему |
|---|---|
| Ноль сторонних зависимостей | «Решение, которое не запускается у жюри, получает 0 за функциональность». Каждая зависимость — это шанс не запуститься |
| Leaflet вручную, не folium | ТЗ разрешает оба. folium — зависимость ради того, что делается шаблоном |
| `csv.reader`, не `csv.DictReader` | DictReader молча проглатывает пустые физические строки, а спека требует считать их в `dropped_rows` |
| Полный перебор, не жадный | Жадный даёт C16+C17 (108) против верного C09+C14 (111). Кандидатов 20, пар 190 — перебор бесплатен |
| Никаких эпсилонов у порогов 500/1000 м | Проверено: `<=1000+1e-9` даёт 113 вместо 111 и ломает эталон |
| Медианы не округляются | Округление симметрично переворачивает риск; критерий зачёта сверяет `cell_id`, а не число |
| Пакет называется `rsrp_coverage` | `coverage` конфликтует с библиотекой coverage.py: у жюри мог бы подхватиться чужой модуль |

Полный реестр с доказательствами — [DECISIONS.md](DECISIONS.md).

## Часть 2. Процесс

### Проблема, которую процесс решает

Сверка с открытым эталоном — **ненадёжный оракул**. Измерено: из 20 поломок
отдельных правил спеки **10 не заметили ни тесты, ни сверка с `expected.json`**.
Среди выживших — полностью выключенная отсечка 500 м и проекция от широты
точки вместо широты начала сетки.

Обычное ревью это тоже не ловит: рецензент читает код и соглашается, что он
выглядит правильно. Он и выглядит правильно.

### Решение: контракт на мутациях

Работа не принимается по описанию. Она принимается по тому, **умирает ли
мутант**.

```
    ИСПОЛНИТЕЛЬ                      КРИТИК
         │                              │
         │  код + тест                  │
         ├─────────────────────────────>│
         │                              │  пишет мутанта:
         │                              │  ломает ровно одно правило
         │                              │
         │        мутант ВЫЖИЛ          │
         │<─────────────────────────────┤
         │  тест ничего не доказывает,  │
         │  работа возвращается         │
         │                              │
         │  усиленный тест              │
         ├─────────────────────────────>│
         │        мутант УМЕР           │
         │<─────────────────────────────┤
         │                              │
         v                              v
              принято, запись в DECISIONS.md
```

Ключевое правило: **критик не видит обоснований исполнителя, пока не напишет
мутанта.** Иначе он подстраивается под чужую гипотезу — это известная болезнь
агентов-рецензентов, они склонны подтверждать то, что им дали.

### Роли

| Агент | Чей | Отвечает за | Не имеет права |
|---|---|---|---|
| `conductor` | свой | распределение работы, арбитраж споров, финальное решение | писать код |
| `devil` | свой | мутанты, попытки сломать, отказ принимать работу | чинить то, что сломал |
| `critic` | свой | соответствие дословной спеке ТЗ | предлагать правки «для красоты» |
| `python-reviewer` | ECC | качество кода, PEP 8, идиомы | трогать числа спеки |
| `silent-failure-hunter` | ECC | проглоченные ошибки, тихие падения | — |
| `pr-test-analyzer` | ECC | осмысленность тестов | — |
| `doc-updater` | ECC | README, документация | — |

### Протокол спора

Разногласие не закрывается тем, что кто-то уступил. Оно закрывается
доказательством и записывается в [DECISIONS.md](DECISIONS.md):

```
### D-07. Нужно ли округлять медианы

**Заявление** (исполнитель): выводить сырой float.
**Возражение** (devil): 23 клетки печатаются как -106.69999999999999;
                        если эталон округлён, сверка не пройдёт.
**Доказательство**: round(v,6) симметрично переворачивает риск — сломается,
                    если эталон хранит сырой float. Критерий зачёта из DOCX
                    сверяет «2 из 3 худших квадратов», то есть cell_id.
**Вердикт** (conductor): не округлять. Риск неустраним, но асимметрии нет.
```

Правило: **вердикт обязан ссылаться на запуск, а не на мнение.** Строка
«кажется правильным» делает запись недействительной.

### Инструмент

`tools/mutate.py` — запускает мутационный набор. Это исполняемый контракт,
а не документ:

```bash
python tools/mutate.py            # все мутанты
python tools/mutate.py --list     # что проверяется
```

Выживший мутант — это провал сборки, а не предупреждение.
