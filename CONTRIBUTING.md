# Как работать в этом репозитории

Короткая памятка для команды. Дедлайн — последний коммит 21.11.2026, 09:00.

## Первый запуск

```bash
git clone https://github.com/Karymshakov/dc.git
cd dc
python main.py ask "Как проверить баланс?"
```

Это должно сразу напечатать JSON. **Устанавливать ничего не нужно** —
основная часть работает на чистой стандартной библиотеке.

Для тестов и бота:

```bash
python -m pip install pytest "python-telegram-bot>=20"
```

> **Если в системе несколько Python**, команда `python` и команда `python3`
> могут указывать на разные установки. Проверьте ту, которой запускаете:
> `python -c "import telegram"`. Упало — ставьте библиотеку именно для неё.

## Секреты

Токены **никогда** не попадают в репозиторий. Скопируйте `.env.example`
в `.env` и впишите свои значения — файл исключён в `.gitignore`.

```
TELEGRAM_BOT_TOKEN=...   нужен только для запуска бота
GEMINI_API_KEY=...       нужен только для голосовых сообщений
OPERATOR_CHAT_ID=...     чат операторов, необязателен
```

Если токен случайно попал в коммит — не прячьте, скажите сразу:
его надо отозвать через `@BotFather` и выпустить новый.

## Перед каждым коммитом

```bash
python tools/check.py
```

Одна команда проверяет контракт жюри, точность, тесты, сторож фактов
и отсутствие секретов. **Красное — не коммитим.**

## Ветки

```bash
git checkout -b имя/что-делаю      # например: alto/voice-bonus
# ...работа...
python tools/check.py
git push -u origin имя/что-делаю
```

В `main` — только то, что прошло проверку. Перед слиянием подтяните чужие
изменения: `git pull --rebase origin main`.

## Кто за что отвечает

Чтобы не править одни файлы одновременно, зоны разделены:

| Область | Файлы |
|---|---|
| Язык ru/ky, нормализация | `faq_bot/lang.py`, `normalize.py` |
| Поиск, синонимы, порог | `faq_bot/knowledge.py`, `search_*.py`, `ranking.py` |
| Контракт жюри | `faq_bot/answer.py` |
| Бот, экраны, диалог | `faq_bot/bot.py`, `presentation.py`, `context.py`, `stats.py` |
| Тексты и правила поведения | `faq_bot/bot_rules.json` — **правится без кода** |
| Измерения | `tools/evaluate.py`, `tools/split.py` |

Берёте задачу — скажите в чате, какие файлы трогаете.

## Что нельзя менять без обсуждения

1. **Формат ответа `answer()`** — по нему считают 40 баллов автопроверки:
   `{"lang", "faq_id", "confidence", "candidates"}`, и ничего больше.
2. **`answer()` не должен зависеть от Telegram, сети и ключей.** Есть тест,
   который блокирует импорт `telegram` и проверяет это.
3. **Файл `data/05_support/holdout.csv`.** Это финальная приёмка, он открыт
   ровно один раз. Настраиваться по нему — значит обесценить метрику.
4. **Пороги и числа ТЗ** в `faq_bot/config.py`.

## Как измерять, что стало лучше

```bash
python main.py eval --split tune --errors    # точность с разбором ошибок
python -m faq_bot.ranking --errors           # сравнение двух методов поиска
```

Правило команды: **утверждение «стало лучше» принимается только вместе
с цифрой до и после.** В `tune` 25 вопросов, один вопрос весит 4 процентных
пункта, поэтому прирост меньше двух пунктов — это шум, а не улучшение.

И главное: `tune` — это набор, по которому мы настраивались, на нём 100%.
Настоящая проверка — вопросы, сочинённые с нуля. Если добавляете синонимы,
придумайте новые формулировки и проверьте на них тоже.

## Запуск бота

```bash
python tools/run_bot.py          # запустить (старые экземпляры погасит сам)
python tools/run_bot.py --status # кто работает
python tools/run_bot.py --stop   # остановить
```

**Одновременно должен работать только один экземпляр.** Telegram отдаёт
очередь сообщений кому-то одному, и два бота начинают мешать друг другу:
часть сообщений теряется, часть обрабатывается дважды. Мы на это уже
наступали — три запущенных бота выглядели как развал интерфейса.
