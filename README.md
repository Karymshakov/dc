# ТЗ 7 «Карта покрытия» — решение

Решение задания 7 межвузовского хакатона INAI 2026. Программа читает замеры RSRP,
очищает их по правилам спеки, строит сетку 200×200 м, находит три худшие клетки,
выбирает пару площадок под новые базовые станции и выводит результат в JSON и HTML-карту.

Данные синтетические (модель района Бишкека), см. `data/extracted/participants/07_coverage/README_RU.md`.

## Быстрый старт

Из корня репозитория:

```bash
python main.py
```

Результат появится в папке `out/`:

- `out/result.json` — ответ по формату ТЗ;
- `out/map.html` — карта покрытия (открывается в браузере двойным щелчком).

Сверка с открытым эталоном:

```bash
python main.py --expected data/07_coverage/expected.json
```

В выводе должна быть строка `сверка с эталоном    : СОВПАДАЕТ`.

## Требования

- Python 3.10 или новее (проверено на Python 3.14).
- Сторонних зависимостей для запуска **нет**: только стандартная библиотека Python.
- `pytest` нужен только для тестов и мутационной проверки (см. `requirements.txt`).
- Для открытия карты нужен интернет: Leaflet 1.9.4 подгружается с `unpkg.com`, подложки карты — внешние тайлы. Сам расчёт и `out/result.json` от интернета не зависят.

## Что реализовано

Пункты ниже соответствуют требованиям раздела 7 `CLARIFICATIONS_RU.md`.

| Требование | Где в коде | Статус |
|---|---|---|
| Чтение `measurements.csv`, `towers.csv`, `candidates.csv`, `bounds.json` | `cleaning.py`, `siting.py`, `cli.py` | сделано |
| Очистка: обязательные поля, конечность чисел, ISO 8601 время, географические границы, дедупликация по `lat, lon, rsrp_dbm, timestamp` | `cleaning.py` | сделано |
| Учёт каждой отброшенной строки в `dropped_rows` (включая пустые физические строки) | `cleaning.py` | сделано |
| Локальная равнопромежуточная сетка 200×200 м, `cell_id = X{ix:03d}_Y{iy:03d}` | `geo.py`, `grid.py` | сделано |
| Медиана RSRP по клетке, минимум 5 замеров | `grid.py` | сделано |
| Три худших клетки: сортировка по медиане, затем по `cell_id` | `grid.py` | сделано |
| Красная зона: медиана < −105 dBm | `grid.py` | сделано |
| Допустимая площадка: расстояние до каждой существующей БС ≥ 500 м | `siting.py` | сделано |
| Покрытие: расстояние до центра красной клетки ≤ 1000 м (гаверсинус, R = 6371000 м) | `siting.py` | сделано |
| Выбор пары площадок по максимуму объединения покрытых красных клеток, тай-брейк по `ID` | `siting.py` | сделано |
| Вывод `result.json` с полями `worst_cells`, `best_candidates`, `dropped_rows`, `covered_weak_cells` | `pipeline.py`, `cli.py` | сделано |
| HTML-карта | `mapping.py` | сделано |

Числа спеки вынесены в один файл: `src/rsrp_coverage/config.py`.

### Результат на данных задания

Совпадает с открытым эталоном `data/07_coverage/expected.json` по всем 4 полям:

| Поле | Значение |
|---|---|
| `worst_cells` | X006_Y013 (−124.5), X005_Y013 (−121.4), X006_Y012 (−120.75) |
| `best_candidates` | C09, C14 |
| `dropped_rows` | 200 |
| `covered_weak_cells` | 111 |

Контрольные числа:

- 5000 строк замеров → 200 отброшено → 4800 замеров;
- 398 клеток с замерами → 387 учтено (≥ 5 замеров), 11 не учтено;
- 174 красные клетки среди учтённых;
- 16 допустимых площадок из 20 кандидатов.

### Карта

- Leaflet, без сторонних Python-зависимостей.
- Переключатель из 4 слоёв подложки: «Светло-серая», «Улицы», «OpenStreetMap», «Без подложки».

## Бонусы

- **Сравнение жадного алгоритма с полным перебором.** Жадный выбор даёт C16 + C17 = 108 клеток, полный перебор даёт C09 + C14 = 111. Жадный промахивается мимо эталона, поэтому в решении используется полный перебор: кандидатов 20, пар 190.

## Структура проекта

```
main.py                      точка входа: python main.py
src/rsrp_coverage/
  config.py                  все числа спеки
  geo.py                     гаверсинус, локальная сетка
  cleaning.py                очистка замеров, дедупликация, dropped_rows
  grid.py                    агрегация по клеткам, медианы, красные, худшие
  siting.py                  допустимость площадок, покрытие, выбор пары
  mapping.py                 HTML-карта на Leaflet
  pipeline.py                сборка полного прогона
  cli.py                     аргументы, вывод, сверка с эталоном
tests/                       тесты правил спеки
tools/mutate.py              мутационная проверка правил
data/07_coverage/            входные данные и expected.json
out/                         результаты запуска (создаётся, в git не попадает)
docs/ARCHITECTURE.md         устройство кода и процесса проверки
```

## Как проверить

```bash
python main.py --expected data/07_coverage/expected.json   # должно вывести СОВПАДАЕТ
python -m pytest -q                                        # тесты, нужен pytest
python tools/mutate.py                                     # мутационная проверка, нужен pytest
python tools/mutate.py --list                              # список проверяемых правил
```

- Тесты: `python -m pytest -q` — 67 тестов.
- Мутационная проверка: `python tools/mutate.py` — убивает 20 из 20 мутантов. Каждый мутант ломает одно правило спеки и должен упасть либо в тестах, либо на сверке с эталоном. Инструмент запускает `pytest`, поэтому без `pytest` он не отработает.

## Известные ограничения и что не успели

**Не сделано:**

- Тепловая карта — **в работе**.
- Сравнение покрытия днём и ночью — **в работе**.

**Ограничения:**

- Карта требует интернета для загрузки Leaflet и подложек. Без интернета `out/map.html` откроется без карты; `out/result.json` формируется без интернета.
- Решение проверено только на данных из `data/07_coverage/`. Поведение на скрытом наборе не измерено.
