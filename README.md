# ТЗ 7 «Карта покрытия» — решение

Решение задания 7 межвузовского хакатона INAI 2026. Программа читает замеры RSRP,
очищает их по правилам спеки, строит сетку 200×200 м, находит три худшие клетки,
выбирает пару площадок под новые базовые станции и выводит результат в JSON и HTML-карту.

Данные синтетические (модель района Бишкека), см. `data/extracted/participants/07_coverage/README_RU.md`.

## Быстрый старт

Из корня репозитория:

```bash
python main.py
```

Результат появится в папке `out/`:

- `out/result.json` — ответ по формату ТЗ;
- `out/map.html` — карта покрытия (открывается в браузере двойным щелчком).

Сверка с открытым эталоном:

```bash
python main.py --expected data/07_coverage/expected.json
```

В выводе должна быть строка `сверка с эталоном    : СОВПАДАЕТ`.

## Требования

- Python 3.10 или новее (проверено на Python 3.14).
- Сторонних зависимостей для запуска **нет**: только стандартная библиотека Python.
- `pytest` нужен только для тестов и мутационной проверки (см. `requirements.txt`).
- Для открытия карты нужен интернет: Leaflet 1.9.4 подгружается с `unpkg.com`, подложки карты — внешние тайлы. Сам расчёт и `out/result.json` от интернета не зависят.

## Бонусы

Сделаны все три бонусных пункта ТЗ.

**1. Сравнение жадного алгоритма с полным перебором.** Жадный выбор даёт C16 + C17 = 108 клеток, полный перебор — C09 + C14 = 111. Жадный промахивается мимо эталона, поэтому в решении используется перебор: допустимых площадок 16, пар 120, считается мгновенно.

**2. Тепловая карта.** Слой интенсивности сигнала поверх клеток, включается в переключателе слоёв, по умолчанию выключен. Интенсивность нормируется по фактическому диапазону медиан в данных, а не по порогам −105/−90. Нарисован своим кодом на canvas: внешний скрипт вроде `leaflet.heat` не используется, чтобы бонус не исчез при отсутствии сети.

**3. Сравнение покрытия днём и ночью.** Отчёт в `out/bonus_day_night.json`, сводка в stdout. День — полуинтервал [07:00, 19:00) по локальному времени, ночь — остальное; граница выбрана так, чтобы половины были равны по 12 часов и выборки сопоставимы (2403 против 2397 замеров).

Результат на открытых данных:

```
день 07:00-19:00     : 2403 замеров, 286 клеток, 137 красных, медиана медиан -104.85
ночь остальное время : 2397 замеров, 283 клеток, 119 красных, медиана медиан -103.00
красные только ночью : 16 клеток (ещё 35 ночью красные, а днём не учтены)
красные только днём  : 25 клеток (ещё 44 днём красные, а ночью не учтены)
```

**Систематической разницы между днём и ночью в данных нет.** Медиана медиан отличается на 1.85 дБ, медианный сдвиг по 208 общим клеткам +0.8 дБ при медианном модуле сдвига 2.4 дБ. Статус «красная» меняют 41 клетка, и все стоят вплотную к порогу −105. Это шум выборки.

Отдельно отмечены клетки, которые нельзя сравнивать: при делении пополам отсечка «≥5 замеров» применяется заново, учтённых клеток становится 286 и 283 вместо 387, поэтому 35 и 44 клетки не имеют пары в другой половине. Они выведены отдельными списками, а не записаны в «ухудшение покрытия».

## Как проверить

```bash
python main.py --expected data/07_coverage/expected.json   # должно вывести СОВПАДАЕТ
python -m pytest -q                                        # тесты, нужен pytest
python tools/mutate.py                                     # мутационная проверка, нужен pytest
python tools/mutate.py --list                              # список проверяемых правил
```

- Тесты: `python -m pytest -q` — 135 тестов.
- Мутационная проверка: `python tools/mutate.py` — убивает 30 из 30 мутантов. Каждый мутант ломает одно правило спеки и должен упасть либо в тестах, либо на сверке с эталоном. Инструмент запускает `pytest`, поэтому без `pytest` он не отработает.

### Зачем мутационная проверка

Совпадение с открытым эталоном — ненадёжный признак правильности. Измерено на этом проекте: из 20 поломок отдельных правил спеки **10 не замечали ни тесты, ни сверка с `expected.json`**. Среди незамеченных были полностью выключенная отсечка 500 м и проекция от широты точки вместо широты начала сетки — то есть `main.py --expected` печатал «СОВПАДАЕТ» при сломанном правиле.

После добавления тестов, где нарушение правила меняет ответ, убиты все 20. Подробнее — [docs/DECISIONS.md](docs/DECISIONS.md), запись D-08.

## Известные ограничения

- **Решение проверено только на открытом наборе `data/07_coverage/`.** Поведение на скрытом наборе жюри не измерено. Мутационная проверка снижает этот риск, но не снимает его.
- **Медианы выводятся без округления**, поэтому часть значений выглядит как `-106.69999999999999`. Округление симметрично переворачивает риск расхождения с эталоном, поэтому не делается — см. [docs/DECISIONS.md](docs/DECISIONS.md), D-05.
- **Подложка карты требует интернета.** Сам Leaflet и иконки маркеров встроены в страницу, поэтому без сети отрисуются полностью клетки, тепловой слой, вышки, выбранные площадки и маркеры худших клеток — не хватит только фона с улицами. `out/result.json` от интернета не зависит вообще.
- **Граница дня и ночи выбрана нами** ([07:00, 19:00) по локальному времени): ТЗ её не задаёт. Выбор обоснован в [docs/DECISIONS.md](docs/DECISIONS.md), D-09, и выводится в отчёт бонуса.
