# Правила ТЗ 7 «Карта покрытия»

Это дословные правила задания и выданных организаторами уточнений (`CLARIFICATIONS_RU.md`,
раздел 7). Они проверяются автопроверкой жюри на скрытом наборе и стоят 40 баллов из 100.

**Ни одно число на этой странице не меняется без явного указания человека.**
Если кажется, что правило странное — оно всё равно исполняется дословно: сверяемся
с эталоном, а не со здравым смыслом.

## Источники

- `data/07_coverage/bounds.json` — границы района и параметры сетки.
- `data/07_coverage/expected.json` — открытый эталон, сверка обязательна после любой правки.
- `data/extracted/participants/CLARIFICATIONS_RU.md` — раздел 7, полный текст правил.

## Очистка замеров

Порядок проверок строго такой:

1. Обязательные поля `lat, lon, rsrp_dbm, timestamp` присутствуют и непустые.
2. Числа разбираются и **конечны**: `NaN` и `Infinity` отбрасываются.
3. RSRP в диапазоне **[-140, -44]**, обе границы **включительно**.
4. `timestamp` — корректный ISO 8601.
5. Координаты внутри прямоугольника `bounds.json`, границы **включительно**.
6. Дедупликация по **четырём** нормализованным полям `lat, lon, rsrp_dbm, timestamp`.
   Числа сравниваются **как числа**: `-98.2` и `-98.20` — один и тот же замер.

`dropped_rows` — количество **уникальных отброшенных строк**, включая пустые.
Это не сумма срабатываний фильтров: строка, нарушившая три правила, считается один раз.

Контроль на открытом наборе: 5000 строк, отброшено 200, осталось 4800.

## Сетка

Локальная равнопромежуточная модель, **не Web Mercator**:

```
lat0 = grid_origin_lat,  lon0 = grid_origin_lon,  R = 6371000
x = R * cos(rad(lat0)) * rad(lon - lon0)
y = R * rad(lat - lat0)
cell = (floor(x / 200), floor(y / 200))
cell_id = f"X{ix:03d}_Y{iy:03d}"
```

Центр клетки — `(ix + 0.5, iy + 0.5) * 200`, преобразованный обратно в `lat/lon`.
Замер на максимальной границе включается по правилу `floor`, без отдельной отсечки индекса.

Медиана RSRP считается по оставшимся замерам клетки. Клетка учитывается
только при **>= 5** замерах.

Контроль: 398 клеток содержат замеры, 11 из них отсеиваются, остаётся 387.

## Цвета и слабые зоны

| Условие | Цвет |
|---|---|
| медиана >= -90 | зелёный |
| -105 <= медиана < -90 | жёлтый |
| медиана < -105 | красный (слабая зона) |

Красная клетка — строго `median < -105`. Ровно -105 это жёлтый.

## Худшие клетки

Сортировка по `rsrp_median`, затем по `cell_id`. Возвращаются первые **3** объекта
вида `{cell_id, rsrp_median}`.

## Выбор площадок

- Площадка **допустима**, если расстояние до **каждой** существующей БС **>= 500 м**.
- Площадка **покрывает** красную клетку, если расстояние до её **центра** **<= 1000 м**.
- Расстояния — **только гаверсинус** с `R = 6371000`. Евклид по градусам запрещён.
- Перебираются **все пары** допустимых площадок, максимизируется **размер объединения**
  покрытых красных клеток.
- При равенстве берётся **лексикографически минимальная отсортированная пара ID**.
- `covered_weak_cells` — размер объединения, **не** сумма покрытий по отдельности.

Жадный алгоритм на этих данных даёт неверный ответ (C16+C17, 108 клеток)
против правильного C09+C14 (111). Он существует только ради бонусного сравнения
и никогда не используется для `result.json`.

## Формат вывода

```json
{
  "worst_cells": [{"cell_id": "X006_Y013", "rsrp_median": -124.5}],
  "best_candidates": ["C09", "C14"],
  "dropped_rows": 200,
  "covered_weak_cells": 111
}
```
